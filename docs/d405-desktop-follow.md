# Intel RealSense D405 与云台小智的桌面跟随

将Intel RealSense D405 固定在桌面一侧并接入 Windows 电脑，镜头同时覆盖座位和来人经过的位置。电脑负责识别人物和判断方向，通过局域网给 ESP32-S3N16R8-Emoji 发送双轴目标角。机器人可用电池供电，小智继续通过 Wi-Fi 进行语音对话。

## 在这台电脑上使用

1. 将 D405 连接电脑即可预览和测距。需要云台跟随时，让已运行本项目云台固件的机器人与电脑接入同一局域网。
2. 用 USB 3 数据线连接 D405，关闭可能占用相机的 RealSense Viewer。仅接一台 D405 时程序会自动选择，多台时在控制台按序列号选择。
3. 在 Windows 双击 `scripts/desktop_follow/start.cmd`，然后打开[本机视觉控制台](http://127.0.0.1:8765)。首次启动需要 64 位 Python（本机使用 3.11），启动器会在 `%LOCALAPPDATA%\XiaozhiFollow\venv` 安装依赖，包括 `pyrealsense2`，并下载校验识别模型。
   如需从手机或其他电脑访问，将这台电脑的局域网 IPv4 地址单独一行写入 `%LOCALAPPDATA%\XiaozhiFollow\lan-ip.txt`，重启控制台后打开 `http://电脑的局域网IP:8765/`。电脑地址变化时更新该文件。删除文件并重启即可恢复仅本机访问。能访问此地址的设备可以查看画面和操作云台，请只在受信任的局域网启用。
4. 在「设备与跟随」填写机器人当前 IP，点击「连接」。确认相机型号后点击主人框，画面会定格。分别录入正脸和轻微侧脸，每次重新取样前点「恢复实时」。在画面拖动框出过道，点「使用框选区域」，也可使用全画面。可选的距离范围以米计，清空两个数值后保存可取消。
5. 在「位置标定」任选一条路径。使用三维时，打开并打印编号相同的 ArUco 图，实测**黑色方块外边长**。标记平放，印刷上边为前、右边为右，填写机器人正前相对标记前方的顺时针角，以及从标记中心到转轴的右、前、上偏移。识别后检查预览的 R/F/U 轴。在座位和过道分别选点「让小智看向选中的点」，必要时保存舵机零偏。
6. 使用二维时，拖出座位或过道，输入区域名称并建立。每个区域分别采集中、左、右、上、下五个参照点。每次点击参照物定格，使用 1° 按钮对准，到位后保存此点。采满五点后自动拟合。用另外两个位置试转验收。深度异常时，程序可使用覆盖该点的二维区域。要重做某个区域，先删除旧区域。
7. 点「开启跟随」。只有主人时跟随主人，来人出现时显示「有人进入」，随后云台慢慢转向来人。未完成适用位置的标定时，页面仍可识别人，舵机保持。跟随中可以继续对话。点板载网页方向键或电脑端微调即可手动接管。关闭跟随可恢复自动动作，退出电脑程序后仍可用电池独立运行小智。

模型、主人特征和标定默认保存在 `%LOCALAPPDATA%\XiaozhiFollow`。点击「清除主人」可删除已录特征。相机图像只在内存中处理。标定按相机序列号、输出模式和机器人 Wi-Fi MAC 区分。移动相机或底座后重新标定。当前 0.40 的主人余弦相似度和 0.27 的其他人阈值需要现场照明下验证。识别模型固定为 OpenCV Zoo 的 YOLOX、YuNet 和 SFace。[模型来源](https://github.com/opencv/opencv_zoo/tree/48b10fa505aeb51fbd127fc60a5c660040e823b7/models)

## 用文字调试小智

在视觉控制台首页点击「大模型调试」，或在部署电脑打开 [文字调试页](http://127.0.0.1:8765/debug)。每次发送都会读取指定设备在智控台绑定的角色提示与模型。Enter 发送，Shift + Enter 换行。页面最多携带最近 8 轮文字，点「新对话」或刷新即可清空。调试范围为角色和文字回复，设备动作、记忆及语音需在板子上验证。选择远程模型时，对话会发给相应的服务商。

文字调试依赖已绑定设备的小智管理服务和 `chat-debug` 容器，支持 OpenAI 兼容模型。若在另一台电脑部署，将 `scripts/desktop_follow/compose.debug.yaml` 的 `chat-debug` 服务合并至小智服务端的 `compose.override.yaml`。在服务端 `.env` 设置 `DEBUG_DEVICE_MAC` 为所绑定设备的 Wi-Fi MAC，`DEBUG_BRIDGE_FILE` 为 `chat_bridge.py` 的绝对路径（Windows 路径使用 `/`）。从服务端 Compose 目录运行 `docker compose up -d chat-debug`，再启动视觉控制台。桥接端口 18765 只绑定本机，局域网浏览器仍使用控制台的 8765 端口。

已有旧版视觉控制台运行时，可在同一个 Python 虚拟环境中从 `scripts/desktop_follow` 运行 `python app.py --chat-only --port 8766`。此时首页的「大模型调试」会打开 8766 端口的页面，相机继续由原控制台管理。新版控制台正常启动后，首页链接使用 8765 端口。

## 一次典型使用

你独自坐在桌前，小智朝向你。有人从你左后方走进提醒区域，小智转向那个人。对方在区域内走动，小智随其改变朝向。对方离开后，小智转回看你。整个过程可以继续和小智对话。你点机器人原网页的方向键时，手动操作立即接管。

## 系统分工

| 位置 | 职责 |
| --- | --- |
| 电脑后台 | 通过 RealSense SDK 采集彩色和深度图。用彩色画面检测人、比对主人特征和维持轨迹，用有效深度估算机器人应该朝向的方向。浏览器关闭后后台仍可工作。 |
| 电脑调试页 | 由后台通过本机 HTTP 提供。预览彩色图、深度叠加图和选中的人。可查看当前测距、选择标定方式、录入主人、划出提醒区域、单次试转和启停跟随。 |
| ESP32 固件 | 提供角度接口、机械限位和舵机控制权切换。Wi-Fi、语音、音乐、OLED 表情及手势采集沿用现有任务。电脑只发送控制消息。图像和主人特征留在电脑端。 |

## 相机接入与测距验收

D405 的理想测距范围为 **7～50 厘米**。可先在镜头前约 20 厘米放置有纹理的物体，用「深度叠加」和取点测距核对轮廓与读数。较远的人物仍可用彩色画面识别，座位和过道建议做二维标定。更换相机后请重新标定云台位置。[D405 产品规格](https://www.realsenseai.com/products/stereo-depth-camera-d405/)

1. 采集进程同时打开 640 × 480、30 fps 的 BGR8 彩色流和 Z16 深度流，从设备读取每个深度计数代表的米数。控制台会显示相机型号、分辨率和深度单位。
2. 程序从同一 SDK 帧组取彩色与深度，检查时间戳，再用 `rs.align` 将深度对齐到彩色像素。两路画面共用一张镜头校正表，深度使用最近邻重采样以保留无效像素。时间不匹配时只使用当帧彩色图。
3. 固定相机后，分别在桌边、正常座位和过道放置平面参照物，用卷尺记录镜头到参照面的距离。在画面中心和边缘抽查读数，移动参照物检查彩色轮廓与深度边缘是否重合。保存各位置有效深度占比、距离偏差和波动。用这些结果在网页上标明三维可用区域。若座位或过道经常读不到深度，为相应位置采集二维标定点。
4. 运行时仅取所选人物上半身框内部的有效深度，使用中位数抑制衣物边缘和背景干扰。深度空洞、明显跳变或过期时，使用该区域已验证的二维标定。两者都不可用时，网页仍然提示来人，云台保持当前朝向。彩色流中断时停止发角度并释放跟随控制权。

## 人物选择

1. **录入主人。** 在网页上选中自己，采集正脸和轻微侧脸。电脑保存本地特征并支持删除和重录。旁人的轨迹编号只在当前运行期间使用。第一版可采用 OpenCV DNN 的人体检测器、YuNet 人脸检测和 SFace 特征比对，配合短时多目标跟踪。模型版本和识别阈值随配置记录，用实际光照下的主人和第二人样本检查误认。
2. **分别处理身份和轨迹。** 人脸用于确认主人。人体框用于维持位置，包括背对相机的人。主人被确认后，侧脸或低头仍沿用同一条轨迹。两人交叉、身份归属不确定时短暂保持原朝向，等待重新分开或重新识别。只有一条身份待确认的轨迹时，可朝向该人，页面显示“身份待确认”，等待更多证据再提示来人。
3. **来人优先。** 默认提醒区域为全画面，可在网页上框选门口、过道等区域。区域内出现与已确认主人同时存在的第二条稳定轨迹即可提醒，也接受有清晰人脸并连续判为其他人的轨迹。主人离开后，已选中的来人仍可继续跟随。多人同时出现时，先选进入区域最早者，持续跟随至其离开，再处理下一人。
4. **抑制误切换。** 初始设置为来人持续出现约 0.5 秒再切换，目标丢失约 1.5 秒再切走。切换期间保留最后朝向。无合格来人时选择主人，画面无人时停在当前位置，继续等待。若主人离场后才出现一名始终背对镜头的人，页面可显示“有人”，其身份保持待确认。

来人一经确认，调试页立即框出对方并显示“有人进入”，云台随后慢慢转过去。默认按画面区域提醒。若过道背景中经常有人经过，可按现场量出的有效距离给提醒区域增加远近范围。启用距离筛选后，范围外的人继续显示在预览中，深度暂时无效的人显示“距离待确认”。两种情况下均保留当前跟随目标，待该人确认进入距离范围后再切换。

## 摆放与网页标定

采用**半自动标定**。相机、机器人底座和人可能分处三个不同位置。固定相机画面中的“居中”，也可能对应机器人向左看。跟随程序每次计算机器人应该朝向的绝对角度。电脑调试页按下列顺序引导操作。

1. **确定覆盖范围。** 选择相机序列号和机器人地址，令云台慢速回中，在画面里圈出座位和提醒区域。让一人从过道进入，确认相机看得见，也确认该方向在云台机械行程内。超出行程时，网页显示“已到限位”，继续提供来人提示。
2. **建立相机与底座的关系。** 将一个已知边长的 ArUco 标记固定在底座旁，记录标记相对云台转轴的位置，并标明机器人正前方。网页根据彩色相机内参和标记四角估计底座的位置与朝向，叠加前方、右方、上方供用户确认。在实际座位放置参照物，微调两轴零偏，分别验证左、右、抬头、低头。日常运行可从电脑加载该姿态。改变相机或底座的位置后重新标定。
3. **验证三维朝向。** 使用对齐到彩色图的深度和匹配的内参，将目标还原为相机坐标中的点，再变换到底座坐标系，以转轴位置为起点计算水平角和俯仰角。分别在座位和过道选取未参与标定的参照物，用“试转一次”验证。再让参照物沿同一视线远近移动，检查相机与机器人分开放置造成的视角差是否得到补偿。
4. **建立二维备用标定。** 对深度不稳定的区域，或标定时底座无法入镜的摆位，在常用距离采集中、左、右、上、下五点。网页定格彩色画面，用 1° 慢速微调让小智看向参照物，保存原图坐标和指令角。拟合二维坐标到两轴角度的映射，排除重复、近似共线的采样，并用两个留出位置试转。远近差明显的座位和过道可分别保存映射。
5. **保存并启用。** 记录相机序列号、彩色与深度模式、标记尺寸和朝向、底座偏移、舵机零偏、二维采样点及机器人标识。相机模式或设备变化时重新验证对应参数。页面显示当前采用“三维”“二维”或“保持”，以及目标角和已输出的指令角。SG90 没有机械角度回读。二维和三维切换时，新的目标沿用固件的同一限速。

## 舵机控制权

固件由同一个 ServoController 管理三种模式。每次启动进入自动模式，网页展示当前控制方。控制的对象只有头部双舵机。

| 事件 | 固件行为 |
| --- | --- |
| 自动模式 | 接受现有小智、手势和表情的舵机动作。 |
| 用户开启跟随 | 切换为跟随模式，中断旧动作的后续舵机写入，只接受当前跟随会话的目标角。AI 和手势仍可触发屏幕反馈。 |
| 用户点击方向键、回中或标定微调 | 立即进入手动模式、作废跟随会话并清除待执行目标。电脑收到接管状态后停止发角度。再次开启跟随需要用户点击。 |
| 用户关闭跟随或按“恢复自动动作” | 切回自动模式，随后响应新产生的自动动作。 |
| 跟随开启，画面正常但无人 | 保持跟随模式和当前头部位置，电脑继续发送心跳。 |
| 电脑休眠、后台退出、相机停止出帧或 Wi-Fi 中断 | 后台可通信时主动释放。否则固件从最后一次有效心跳起约 3 秒后恢复自动模式。电脑重连后显示待开启。 |

复用已有舵机互斥锁，把手动标志扩展成控制模式。模式切换时递增代号。多步动作和延迟回中的操作在启动时记录代号，每次写舵机前核对，以免旧动作跨越一次跟随会话后又把头拉回。排队的表情可继续播放，随附的舵机动作同样核对代号。固件用独立的周期检查处理超时，即使电脑完全停止请求也能交还控制权。

## 舵机限速与手动回中

手动回中向运动任务提交双轴 90° 目标。手动方向键、回中、标定试转、视觉跟随、手势和 AI 动作都只提交目标角度，由 ESP32 的同一个运动任务逐步输出 PWM。这样即使电脑断开，手机直接访问板载页面也能慢速回中。

- **指令速度上限。** 在电脑的「位置标定 → 舵机微调」或板载网页选择手动速度，可选 5、10、15、20°/秒，默认 10°/秒。开发板保存档位，手动微调、回中和单次试转共用这个设置。跟随和自动动作的上限为 10°/秒。两轴同时动作时按剩余行程共享速度，接近目标时减速。位置图中的绿色小脸表示当前输出的指令角，黄色虚线框表示移动目标。
- **每次只走一小步。** 运动任务以 50 Hz 更新。默认速度下两轴每 20 毫秒合计最多推进 0.2°，手动设为 20°/秒时最多推进 0.4°。内部保留小数角度，最后一步换算为 PWM 占空比。调度延迟时丢弃错过的步数。
- **回中和改目标。** 点「回中」只把目标设为水平 90°、垂直 90°。重复点回中沿用当前进度。途中点反方向、切换模式或收到新的跟随角度时，从当前已输出的指令角平滑过渡。点头、摇头等多段动作按到达各段目标的时间衔接，连点和动画均受同一上限约束。
- **状态与适用范围。** 页面区分目标角和当前已输出的指令角，到位前显示“回中中”或“移动中”。SG90 没有轴角反馈。上述速度约束适用于已经建立起始指令角后的运行过程，断电后舵机被手动掰动时，首次上电的机械位置未知。

**回中验收。** 选择 10°/秒，从 95° 回到 90°，单轴用时至少 0.5 秒。再从水平 50°、垂直 90° 回中，水平 40° 行程至少 4 秒。从水平 50°、垂直 70° 同时回中时，总行程 60°，至少 6 秒。计时从开始移动到固件输出最终角度，平滑起停可使实际时间更长。分别测试单击、连续点回中和途中反向，检查 PWM 输出记录中的逐步变化（考虑一个 PWM 计数的量化误差），并观察实物是否猛甩、卡顿或引起掉电重启。

## 局域网接口

保留现有 `GET /api/state` 和 `POST /api/control`。状态响应新增 `mode` 和模式代号 `generation`，保留旧页面使用的字段。固件每次重启生成新的启动标识，用它和 generation 一起校验，防止重启前的报文重新开启跟随。现有手动方向键继续每次 5°，为调试页另加双轴绝对角度的手动指令。新增 `POST /api/follow`，采用小型 JSON 消息，沿用现有控制请求头。

| 操作 | 请求和响应约定 |
| --- | --- |
| start | 用户点击开启时附上刚读取的启动标识、generation 和请求编号。固件按当前代号检查后创建会话并返回 session。相同请求重试只返回原结果，过时代号拒绝。 |
| update | 携带 session、递增序号和可选的两轴整数角度。无角度表示心跳。固件拒绝已过期会话和旧序号。重复包不延长会话。 |
| stop | 释放指定 session。迟到的 stop 不能关闭后续会话或改变手动模式。 |

电脑只保留最新目标，初始发送上限为每秒 5 次，位置不变时每秒发一次心跳。ESP32 在锁内更新两轴目标，校验水平 50°～130°、垂直 70°～110°，按速度限制逐步移动。HTTP 处理函数立即回包。跟随期间，失去目标时取消尚未执行完的移动。为此 update 支持明确的 hold 标志，将目标置为当前指令角。后台只有收到新鲜相机帧时才续期。页上显示限位、离线和被手动接管的原因。

## 实施顺序与现场验收

| 阶段 | 可以现场检查的结果 |
| --- | --- |
| 1. 固件限速、控制权与角度接口 | 先用板载网页完成慢速回中验收，再验证手势和 AI 动作经过相同限速。用测试客户端发绝对角度，检查双轴限位。运动中手动接管、重放旧指令、断开客户端，分别验证手动优先和超时恢复。同时进行一次小智语音对话。 |
| 2. D405 取流与标定页 | 控制台能枚举 D405。网页能预览彩色图和对齐深度、查看取点距离。用桌边、座位和过道的卷尺读数核查距离单位。在两处留出点试转，遮住深度视野或提供无效深度帧，验证二维回退和保持，确认切换时云台仍缓慢移动。 |
| 3. 人物选择 | 先在预览上验证主人独处、主人侧脸、两人交叉、背对镜头进入、多人和空画面。框选目标符合预期后接入云台，让两人按相同路线再走一遍。 |
| 4. 整机共存 | 跟随来人时对话并做手势，头部持续由跟随程序控制。关闭网页后台仍工作。拔掉相机或停止后台后，固件能响应新的自动动作。单独用电池启动时可正常使用小智。 |
